## 1. 背景与目标

### 1.1 旧设置页的问题
1. 「工作交付偏好」三根滑杆（交付详略 / 推进方式 / 证据要求，0–100）含义抽象，用户不知道滑杆会让 Agent 具体改变什么，而且和产品核心「多 Agent 接力协作」关系不大。
2. 分类放错：「Skill 信任」属于安全，却放在「通用」里；「知识库」属于集成，却放在「Agent」里。
3. Agent 用卡片轮播展示（3/14），一屏只能看到几个，信息只有「已安装 / 未安装」。
4. 缺少产品最需要的设置：编排规则、权限、并发冲突、成本控制。用户现在要在每条消息里手写「每次只叫醒一个」「Pi 做完后停在这里，不要再叫醒别人」，这些本该是配置项。

### 1.2 目标
- 把用户手写在 prompt 里的协作规则变成**可配置、可继承、可审计**的设置。
- 建立「全局 → Room → Agent」三层设置，避免全局页越来越臃肿。
- 每个设置项都能回答「改了它，Agent 的行为会怎么变」。
- 安全、成本相关设置默认保守，危险操作要明确提示并二次确认。

## 2. 设计原则（实现时遇到模糊处按这几条判断）

1. **三层设置，下层覆盖上层**：Agent > Room > 全局。**例外：安全类和成本类设置取三层中最严格的值**，下层只能收紧，不能放宽（§4.3）。
2. **一个东西只在一处管理**：其他地方只放摘要和跳转链接。例如 Skill 信任列表只在 Skills 页维护，权限页只放策略，再加一个「在 Skills 页管理 →」链接。
3. **每个设置项都配一句说明**：标签下方用灰色小字写一句，说清楚它对 Agent 行为的影响，不写空话。
4. **规则透明**：凡是会注入 prompt 的设置（全局指令、上下文传递、Skills），都要能预览实际注入的内容和 token 估算。
5. **危险操作醒目**：琥珀色表示有风险，需要确认；红色表示不可撤销，需要输入确认。

## 4. 三层覆盖模型（核心逻辑，务必先实现）

### 4.1 解析规则
```
普通设置：有效值 = Agent 层 ?? Room 层 ?? 全局层 ?? 内置默认值
安全 / 成本类：有效值 = 三层中最严格的值
列表类：按下表各自的规则合并
```

### 4.2 各设置项可以在哪层设置，以及怎么合并

| 设置项 | 全局 | Room | Agent | 合并规则 |
|---|---|---|---|---|
| 默认 Captain | ✓ | ✓ | — | Room 覆盖全局 |
| 每次最多唤醒数 | ✓ | ✓ | — | 覆盖 |
| 接力链最大步数 | ✓ | ✓ | — | 取较小值（成本类） |
| 交接前需要我确认 | ✓ | ✓ | — | 任一层为「是」即为「是」 |
| 允许 Agent 自行 @ 用户 | ✓ | ✓ | — | 覆盖 |
| 上下文传递方式 | ✓ | ✓ | — | 覆盖 |
| 超时阈值 / 失败策略 / 重试次数 | ✓ | ✓ | ✓ | 覆盖 |
| 执行权限（只读 / 询问 / 自动） | ✓（逐个 Agent） | ✓ | ✓ | **取最严**：只读 > 每次询问 > 自动执行 |
| 文件写入范围 | ✓ | ✓ | ✓ | 取交集（范围最小者） |
| 命令黑名单 | ✓ | ✓ | ✓ | 三层取**并集** |
| 命令白名单 | ✓ | ✓ | ✓ | 下层覆盖；黑名单优先于白名单 |
| 允许联网 | ✓ | ✓ | ✓ | 任一层为「否」即为「否」 |
| Skills 启用 | ✓（安装 + 分发） | ✓（从已分发里选子集） | ✓（启用开关） | Room 只能在全局已启用的范围里再缩小 |
| 全局指令 | ✓ | ✓ | ✓（系统指令） | **拼接**，顺序：全局 → Room → Agent；全局可关闭「允许覆盖」 |
| 工作目录 | 默认项目目录 | 绑定目录 | 默认工作目录 | Room 绑定 > Agent 默认 > 全局默认 |
| 并发冲突处理 | ✓ | ✓ | — | 覆盖 |
| 预算 | 月预算 | 单日上限 | — | 各自独立生效，任一触发即执行 |
| 默认模型 / 启动参数 / 环境变量 | — | — | ✓ | 仅 Agent 层 |

### 4.3 「只能收紧」的实现约束
- Room 或 Agent 层试图放宽时（比如全局是「每次询问」，Room 想设成「自动执行」），控件允许选择，但要弹出二次确认，并在该项旁边常驻琥珀色徽章「比全局更宽松」。
- **全局设置里的「锁定」**：安全类设置项旁边有一个锁图标，管理员或用户锁定后，下层不能放宽（控件置灰，悬停提示「已在全局锁定」）。v1 可以先只做数据字段，不做 UI。

### 4.4 UI 表现
- 下层页面里，每个可继承的设置项右侧显示状态标签：`继承全局`（灰色）或 `已覆盖`（青绿），后者带一个「↺ 重置为继承」按钮。
- 全局页的设置项如果在某些 Room 里被覆盖，标签下方显示一行小字：「在 2 个 Room 中被覆盖 · 查看」。
- Room 抽屉的每个页签顶部有分段控件「继承全局 / 自定义」（效果图 07）。选「继承全局」时，下方控件以只读方式展示当前有效值。

## 5. 通用框架与组件规范

### 5.1 布局
- 三栏：应用侧边栏（现有，约 200px）| 设置导航（约 200px）| 内容区（最大宽度 880px，左对齐，内边距 32px）。
- 内容区顶部是页面标题（20px / Semibold）和副标题（13px / 次要色，一句话说明本页用途）。
- 内容按卡片分块：圆角 10px，1px 边框，卡片间距 16px。卡片标题左侧放 16px 线性图标。
- 窗口宽度小于 1100px 时，设置导航折叠成只显示图标（悬停显示名称）。

### 5.2 设置内搜索
- 索引范围：每个设置项的标签、说明文字、同义关键词（比如「死循环」能搜到「接力链最大步数」，「API Key」能搜到「密钥管理」）。
- 结果下拉列表显示路径，比如「协作与编排 › 交接规则 › 接力链最大步数」。
- 点击结果后：跳转到对应页面，滚动到该项，让它高亮闪烁 1.5 秒（青绿底色淡出）。
- 搜索也要覆盖 Room 和 Agent 层的设置项，结果里标明层级。

### 5.3 设置行的结构
```
[标签 14px 主色]                       [控件]
[说明 12px 次要色，一句话]        [可选：继承/覆盖标签]
```
- 徽章种类：`推荐`（青绿描边）、`危险`（琥珀）、`已覆盖`（青绿）、`继承全局`（灰）、`Beta`（灰）。

### 5.4 保存模型（统一约定）
| 类型 | 保存方式 |
|---|---|
| 单个开关、分段控件、下拉框 | **即时生效**，右下角弹出提示「已保存」，2 秒后消失，提示里带「撤销」 |
| 复杂表单：协作与编排、全局指令编辑器、Room 抽屉、Agent 配置 | 修改后底部出现粘性条「有未保存的更改 · 重置 · 保存」（效果图 02）；切换页面或关闭窗口前拦截并询问 |
| 危险操作 | 弹窗确认后才生效（§5.7） |

### 5.5 颜色（深色主题）

| 用途 | 值 |
|---|---|
| 背景 | `#1b1f22` |
| 卡片 / 面板 | `#22272b` |
| 边框 | `rgba(255,255,255,0.08)` |
| 主文字 / 次要文字 | `#E6E8EA` / `#8B9298` |
| 强调（青绿） | `#3fb8b0` |
| 成功 | `#3ecf8e` |
| 警告（琥珀） | `#F5A524` |
| 危险（红） | `#F2555A` |

浅色主题沿用同一套语义 token，具体色值由设计补充。

### 5.6 状态标签用词（全站统一，不要混用）
- Agent：`已就绪`（绿）、`需要登录`（琥珀）、`未安装`（灰）、`异常`（红，悬停显示原因：路径无效 / 版本过低 / 启动失败）
- MCP / 服务：`运行中`（绿）、`已停用`（灰）、`启动失败`（红，附「查看日志」）
- Skill 信任：`已信任`（绿）、`内容已变更`（琥珀）、`未信任`（灰）
- 知识库：`已连接`（绿）、`CLI 未安装`（琥珀）、`尚未选择库目录`（琥珀）

### 5.7 危险操作分级
| 级别 | 例子 | 交互 |
|---|---|---|
| L1 有风险 | 开启自动执行、关闭并发冲突处理、文件写入范围设为「不限制」、开启联网 | 弹窗写明后果（比如「Pi Agent 将不经确认直接运行命令和修改文件」），按钮「我了解风险，开启」；开启后对应位置常驻琥珀标识 |
| L2 不可撤销 | 删除所有会话、重置所有设置、删除共享库 Skill | 弹窗要求输入确认词（比如输入「删除」），按钮是红色 |

### 5.8 空态 / 加载 / 错误
- 每个列表都要有空态文案和主操作按钮（比如云 Agent：「还没有连接 · 连接服务器」，用虚线框卡片）。
- 检测类操作（刷新检测、测试连接）在按钮上显示加载动画，结果直接显示在该行，不弹窗。
- 读写配置失败：在顶部显示红色横幅「无法写入 ~/.claude.json：权限不足」，附「重试」和「打开所在目录」。

### 6.1 Agent 管理（效果图 01）

**用途**：管理本地 CLI Agent 和云端 Agent，检测状态，配置默认参数。

**顶部操作**：`刷新检测`、`+ 添加自定义 Agent`（主按钮）。
**页签**：`本地 Agent (n)` / `云 Agent (n)` / `Connector`

#### 本地 Agent 列表
| 列 | 内容 |
|---|---|
| Agent | 图标 + 名称 |
| 状态 | 状态标签（§5.6） |
| 版本 | 由 `<cli> --version` 解析；版本低于适配器要求的最低版本时显示琥珀色「版本过低」 |
| CLI 路径 | 等宽字体；可点击修改（打开文件选择器） |
| 鉴权 | 「已登录 OpenAI」/「API Key · 钥匙串」/「未鉴权」；未鉴权时显示「去登录」 |
| 操作 | `测试连接`；未安装时显示 `安装`；行尾的展开箭头 |

**检测逻辑**（每个 Agent 一个适配器，适配器提供以下方法）：
- `detect()`：先查用户配置的路径，再查 `PATH` → 返回路径和版本
- `checkAuth()`：调用 CLI 自带的鉴权状态命令，或检查对应的环境变量 / 钥匙串条目
- `testConnection()`：用一个空任务启动 CLI，超时 15 秒；成功时显示「连接正常 · 1.2s」，失败时显示错误输出的前 3 行，附「查看完整输出」
- 触发时机：打开本页、点「刷新检测」、应用启动时（后台静默执行，结果用于更新侧边栏的状态圆点）

**安装**：点「安装」后弹窗显示安装命令（比如 `npm i -g …`），提供「复制命令」和「在终端中执行」两个选项（后者需确认），安装完成后自动重新检测。

#### 行内展开：Agent 配置（与 Agent 详情页「配置」页签共用同一个组件）
| 字段 | 控件 | 默认值 | 说明 |
|---|---|---|---|
| 默认模型 | 下拉框 | 适配器提供的默认值 | 选项由适配器提供；支持手动输入自定义模型名 |
| 默认工作目录 | 路径输入框 + 选择按钮 | 跟随全局默认项目目录 | Room 绑定了目录时，以 Room 的为准 |
| 启动参数 | 等宽输入框 | 空 | 追加到 CLI 命令末尾；保存前做参数解析校验 |
| 环境变量 | 键值对标签 + 添加 | 空 | 值可以引用钥匙串中的密钥（`{{keychain:OPENAI_API_KEY}}`），**明文的敏感值保存时提示改存钥匙串** |
| 系统指令 | 多行编辑器（等宽字体） | 空 | 标签显示目标文件名（CLAUDE.md / AGENTS.md / GEMINI.md）。两种模式：①「Tyche 注入」（默认，不改动用户文件，启动时注入）；②「写入项目文件」（直接编辑工作目录下的同名文件）。附「在单独页面中编辑」链接 |

#### 添加自定义 Agent（弹窗）
| 字段 | 控件 | 说明 |
|---|---|---|
| 名称 / 图标 | 输入框 / 图标选择 | 名称用于 @mention，不能重名，只能用字母、数字和连字符 |
| 接入方式 | 分段控件：CLI 命令 / ACP / MCP / HTTP | 决定下面显示哪些字段 |
| 命令路径 | 路径输入框 | CLI 方式必填 |
| 参数模板 | 等宽输入框 | 支持变量 `{prompt}` `{cwd}` `{model}`，比如 `--print {prompt}` |
| 输出格式 | 下拉框：纯文本 / JSON 流 | 决定 Tyche 怎么解析回复和 token 用量 |
| 检测命令 | 输入框 | 默认 `{path} --version` |
| 权限映射 | 下拉框 | 这个 CLI 是否支持原生权限参数；不支持时由 Tyche 在执行层拦截（§6.4） |

保存前必须先通过「测试连接」。

#### 云 Agent / Connector 页签
- 云 Agent：列表结构与本地相同（状态、服务器地址、鉴权）。空态是虚线框卡片「还没有连接云 Agent · 连接服务器」。
- Connector：沿用现有的「Connector 管理」和「配置服务器」功能，移到这个页签里。

### 6.2 Skills（效果图 05）

**用途**：集中管理所有 Agent 的 Skill，写一次就能分发给多个 Agent。

#### 概念
| 来源 | 存放位置 | 说明 |
|---|---|---|

- 按钮：`浏览市场`、`从 Agent 导入`（扫描所有 Agent 的原生目录，勾选后提升到共享库）、`+ 新建 Skill`（主按钮）
- 筛选标签：`全部 n` · `共享库 n` · `Agent 原生 n` · `市场 n` · `需重新授权 n`（琥珀色）；外加一个搜索框

| 列 | 内容 |
|---|---|

| 每个 Agent 一列 | 单元格有三种状态：开关开（已分发并启用）/ 开关关 / 「—」（这个 Agent 的格式不支持，悬停说明原因） |
| 信任 | 信任状态标签 |
| 更新 | 相对时间 |

**单元格开关的行为**：
- 共享库 skill **打开** → 分发到该 Agent 的 skill 目录。默认用复制加格式转换；适配器支持时可以用符号链接。分发出去的文件里写入标记 `tyche-managed: true` 和内容哈希。
- 共享库 skill **关闭** → 从该 Agent 的目录移除 Tyche 分发的副本（只删带 Tyche 标记的文件）。
- 原生 skill **关闭** → 把它移到 Tyche 的停用区（`…/Tyche/disabled/<agent>/<name>`），不直接删除，可以恢复。
- 未信任的 skill：开关置灰，悬停提示「请先信任此 Skill」。

**信任机制**：
- 用户点「信任」时，记录内容哈希（SKILL.md 加同目录下所有文件）。
- 每次启动 Agent 前和每次打开本页时校验哈希；不一致就标为「内容已变更」。如果「内容变更后自动撤销信任」开着（§6.4），撤销信任并停止注入这个 skill，直到重新授权。
- 信任状态按「skill + 哈希」记录，与 Agent 无关。

**同名冲突**：多个 Agent 里有同名、但哈希不同的原生 skill 时，在该行显示琥珀色警告「同名冲突：Claude 与 Pi 版本不同」，并提供：
- `对比`：左右两栏的差异视图
- `合并`：选一个版本提升到共享库，再分发给所有相关 Agent（覆盖前自动备份）

#### 右侧详情面板（选中某一行后滑出，宽约 320px）
- 名称、版本、来源，以及描述（取自 SKILL.md 的 frontmatter）
- **已分发到**：列出每个 Agent 的图标和实际路径（等宽字体，带复制按钮）
- SKILL.md 预览（只读，前 20 行）
- 按钮：`分发到其他 Agent`、`打开源文件`（用系统默认编辑器打开）、`撤销信任`（红色文字）

#### 新建 Skill（弹窗或整页）
字段：名称（连字符命名）、描述、SKILL.md 编辑器（带模板）、目标 Agent（多选）、附件文件。保存后进入共享库，并自动标记为已信任（因为是用户自己创建的）。

#### 交接规则
| 字段 | 控件 | 默认值 | 说明 |

### 6.4 权限与安全（效果图 03）

**用途**：控制每个 Agent 能读写什么、能执行什么。

#### 执行权限矩阵
- 每个 Agent 一行，右侧是三段控件：`只读` / `每次询问` / `自动执行`。
- 默认值：所有 Agent 都是「每次询问」。
- 切换到「自动执行」时触发 L1 确认弹窗。确认后这一项显示琥珀色加警告三角，页面右上角出现常驻横幅「n 个 Agent 处于自动执行模式」，导航项上显示琥珀点。
- **实现方式**：由适配器把这三档映射到各 CLI 的原生权限 / 沙箱参数。CLI 不支持原生参数时，由 Tyche 在执行层拦截工具调用：「只读」拒绝所有写入和命令，「每次询问」在 Room 里弹出审批卡片。具体映射写在各适配器的文档里。

#### 文件与命令
| 字段 | 控件 | 默认值 | 说明 |
|---|---|---|---|
| 文件写入范围 | 下拉框：仅当前工作区 / 工作区 + 指定目录 / 不限制 | **仅当前工作区** | 选「不限制」触发 L1 确认 |
| 命令白名单 | 等宽标签 + 添加 | `git status` `npm test` `ls` | 在白名单里的命令，即使是「每次询问」模式也不再询问 |
| 命令黑名单 | 红色等宽标签 + 添加 | `rm -rf` `sudo` `git push --force` | 无论什么模式都会拦截；**黑名单优先于白名单**；三层取并集 |
| 允许联网 | 开关 | 关 | 只管 Agent **执行的命令和工具**能不能访问网络，**不影响 CLI 本身调用模型 API**。说明文字要写清这一点，避免用户误解 |

**命令匹配规则**：把命令按 shell 语法拆成词后做前缀匹配（`git push --force` 能匹配 `git push --force origin main`）；管道和 `&&` 连接的每一段分别检查；匹配时忽略多余的空格。

| 禁止 Skill 执行联网命令 | 关 |

#### 密钥管理（底部右栏）
- 列表：变量名 + 掩码值（`••••3f9a`，只显示后 4 位）+ 标签「存储于 macOS 钥匙串」+ 菜单（查看 / 替换 / 删除；「查看」需要系统身份验证）。

- `+ 添加密钥`：填变量名和值，可选「限定可用的 Agent」。

## 7. 数据模型（参考）

```ts
// 内置默认值 ← global.json ← rooms/<id>.json ← agents/<id>.json
type PermissionMode = 'readonly' | 'ask' | 'auto';
type ContextMode = 'full' | 'summary' | 'last';
type FailurePolicy = 'retry' | 'return_to_captain' | 'notify';
type ConcurrencyMode = 'worktree' | 'filelock' | 'none';
type MergeMode = 'auto' | 'captain' | 'review';

interface OrchestrationSettings {
  captainAgentId?: string;
  maxWakePerTurn?: number;        // 1–4，默认 1
  maxChainSteps?: number;         // 1–50，默认 8
  confirmBeforeHandoff?: boolean; // 默认 false
  allowAgentMentionUser?: boolean;// 默认 false
  contextMode?: ContextMode;      // 默认 'summary'
  timeoutMinutes?: number;        // 默认 10
  onFailure?: FailurePolicy;      // 默认 'return_to_captain'
  retryCount?: number;            // 默认 2
  templateId?: string;
}

interface SecuritySettings {
  permission?: Record<AgentId, PermissionMode>; // 默认 'ask'
  writeScope?: { mode: 'workspace' | 'workspace_plus' | 'unrestricted'; extraPaths?: string[] };
  commandAllow?: string[];
  commandDeny?: string[];   // 三层取并集
  allowNetwork?: boolean;   // 默认 false
  locked?: string[];        // 被全局锁定的字段路径（v1 只存数据）
}

interface SkillPolicy { untrustedByDefault: boolean; revokeOnChange: boolean; denySkillNetwork: boolean; }

interface SkillRecord {
  id: string; name: string; version?: string;
  source: 'shared' | 'native' | 'market';
  ownerAgentId?: string;          // source 为 native 时
  hash: string;
  trust: { trustedHash?: string; trustedAt?: string };
  distribution: Record<AgentId, { enabled: boolean; path: string; managed: boolean } | 'unsupported'>;
}

interface RoomSettings {
  workspace?: { path: string; concurrency?: ConcurrencyMode; mergeMode?: MergeMode; autoCleanup?: boolean };
  orchestration?: OrchestrationSettings;
  security?: SecuritySettings;
  skills?: { mode: 'inherit' | 'custom'; enabled?: Record<AgentId, string[]>; perStep?: Record<StepId, string[]> };
  instructions?: string;
  dailyBudgetUsd?: number;
}

interface AgentConfig {
  adapter: string;                 // 'claude-code' | 'codex' | 'pi' | 'gemini' | 'custom'
  cliPath?: string; model?: string; args?: string;
  env?: Record<string, string>;    // 值可以是 '{{keychain:NAME}}'
  defaultCwd?: string;
  systemInstructions?: { mode: 'inject' | 'file'; content: string };
  overrides?: { orchestration?: Partial<OrchestrationSettings>; security?: SecuritySettings };
}

interface RoomTemplate {
  id: string; name: string;
  steps: { id: StepId; label: string; agentId: string; skills?: string[]; instructions?: string;
           then: 'next' | 'stop' | 'captain' }[];
}

interface BudgetSettings {
  monthlyUsd?: number; warnAtPercent: number; // 默认 80
  onExceed: 'warn' | 'pause'; chainMaxTokens?: number; // 默认 200000
}
```

**存储位置**：设置用 JSON 文件存在应用数据目录；密钥只存在系统钥匙串；需要能导出和导入（导出时自动去掉密钥）。

**统一接口**：前端所有地方都通过一个 `resolveEffective(path, roomId?, agentId?)` 读取有效值。这个函数同时返回 `{ value, source: 'default'|'global'|'room'|'agent', looserThanGlobal: boolean }`，UI 的「继承 / 已覆盖 / 比全局更宽松」标签都靠它驱动。

## 8. 编排引擎需要配合的运行时改动

设置页只是开关，下面这些需要引擎侧实现，设置才真正生效：

1. **唤醒上限**：解析 @mention 时按 `maxWakePerTurn` 截断，超出的部分渲染成灰色并附提示。
2. **接力链计数**：每条用户消息生成一个 `chainId`，每次交接 `step++`；达到上限时暂停并插入系统消息（§6.3）。
3. **循环检测**：在滑动窗口里检测 A↔B 往返，达到 3 轮就中止并上报用量统计。
4. **交接确认卡片**：`confirmBeforeHandoff` 打开时，交接请求先变成待审批状态。
5. **上下文组装**：按 `contextMode` 组装上下文，并保存实际注入的内容，供交接卡片展开查看。
6. **超时 / 失败策略**：监测输出心跳，超时后按策略执行。
7. **权限执行层**：工具调用和命令执行前统一检查：权限模式 → 黑名单 → 白名单 → 写入范围 → 联网；检查不通过时根据模式拒绝或弹审批卡片。
8. **Skill 注入**：启动 Agent 前计算有效的 Skill 集合（全局分发 ∩ Room 启用 ∩ 当前步骤），校验哈希和信任状态。
9. **Worktree 生命周期**：创建、交接时合并、最终合并、清理。
10. **用量采集**：每次调用后记录 `{agent, room, chainId, tokensIn, tokensOut, costUsd, estimated}`。
11. **预算闸门**：唤醒 Agent 前检查月预算、Room 单日上限、接力链 token 上限。
12. **指令拼接**：全局 → Room → Agent → Skills 清单；「预览最终 Prompt」调用同一个函数，保证预览和实际注入一致。
