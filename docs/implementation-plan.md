## 1. 原则

1. **风险先行**。各模块文档累积的待实测项决定后续设计是否成立，放在最前面。实测不通过时，先改文档、再继续，而不是带着未验证的前提往下写代码。
2. **由下往上，每层可单独验证**。受管理进程 → 调度器 → 影子仓库 → 存储与接口 → 引擎与调用 → 界面。每个里程碑都有不依赖界面的自动化测试。
3. **每个里程碑只验收本层**。模块文档的测试清单是按模块写的，其中一部分依赖后续里程碑才实现的模块（例如 M1/M5 的 `decideGate` 依赖 M2 引擎）。这些测试在早的里程碑里用**测试替身**验证本层的接口约定（例如用一个假的引擎验证调度器接口的调用顺序），真实的跨模块集成测试统一放在里程碑 5「补跑」。任务单的验收一节逐条写明哪些测试在本里程碑运行、哪些推迟到哪里。
4. **不破坏现有功能**。除了架构第 6 节列出、已经确认的边界变更（A14 作用于所有可能写入的调用、可写 ACP 调用每轮启动、与项目重叠的普通群聊写入互斥），现有群聊的行为不变。每个里程碑都运行全部现有测试。
5. **项目室在功能开关后面**。界面入口在里程碑 8 验收之前默认隐藏（设置中的「项目室（预览）」开关），避免半成品出现在用户面前。A14 不受这个开关控制，它作用于所有群聊，见里程碑 1。
6. **验证命令**（`AGENTS.md`）：`npm --prefix frontend test`、`npm --prefix frontend run build`、`npm --prefix frontend run build:desktop`、`npm --prefix desktop test`、`npm --prefix desktop run pack`。涉及聊天行为的改动，在 Electron 桌面模式中人工检查。每个里程碑的验收报告写明运行了哪些命令、哪些验证没有完成。

**范围**：`desktop/src/agents/process/`（监护程序、受管理启动器、进程登记表）；`cli-process-support.cjs` 的 `terminateAgentProcess`；`cli-adapters.cjs`、`cli-acp-runner.cjs` 的 `spawnFn` 与终止路径；可能写入的 ACP 调用改为每轮一个进程；应用启动时的进程登记表恢复与残留占用的登记（先登记到一个临时的内存结构，里程碑 2 接入调度器）；`atomicWritePrivateFile` 的 `phase`（M1/M5 6.1，进程登记表放行前需要）。

### 里程碑 9：现有模式的限制、迁移与发布准备

## 5. 风险与应对

| 风险 | 影响的里程碑 | 应对 |
| --- | --- | --- |
| 监护程序在打包后的 Electron 中行为与原型不同 | 0、1 | 里程碑 0 首先验证；备选为独立的小程序 |
| Claude、Codex 的 ACP 适配器实测不通过 | 0、5、7 | 保留 print/exec 通道；完整轨迹在回退通道中按 M7 的映射提供，能力登记如实标注 |

| 可写 ACP 调用每轮启动的延迟过大 | 0、1 | 评估 M3 第 13 节第 5 条的替代方案，改文档后再实现 |
| 大仓库上快照过慢 | 0、3 | 调整默认上限与排除规则；核对快照失败闭合，不会因此产生错误结论 |
