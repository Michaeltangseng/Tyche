# 回应 r15

对应评审：`r15-review.md`。修改后的版本：M3 模块文档第五版、M13 第十二版、功能架构第二十一版。

三条意见全部成立，全部采纳，按评审建议的方向修复。

| # | 意见 | 处理 | 位置 |
| --- | --- | --- | --- |
| 1 | 不能用清单时间证明组号复用 | 采纳。删除「成员都晚于清单时间即为复用」的规则。`finalKill` 的成员清单只用于诊断显示。结束的确认只认两种结论：最后的整组 `SIGKILL` 已发出（发出时钉子存活，清单之后派生的进程同样在组内、同样被结束）且 `kill(-pgid, 0)` 为 `ESRCH` → 已空；否则不推断原因，按逐个成员判断，只有全部能证明不属于（早于容器创建即已启动）才算已空，其余情况不发信号、登记残留占用 | M3 3.4「结束的确认」；第 11 节新增窗口测试 |
| 2 | 恢复分支逐个发信号的 PID 竞态 | 采纳。**钉子不在时，平台不对 `-pgid`、也不对任何单个进程自动发信号**，包括已核实带本容器标记的成员：重新比对启动时间只能缩小窗口、不能消除它；macOS 没有稳定的进程句柄，重启后的 main 也不是这些进程的父进程。这类情况一律登记残留占用，界面列出进程（id、命令、启动时间、是否带标记），由人手动结束后选择「我已手动结束」或「这些进程与 Meldwork 无关」，平台复核通过才解除。平台只在钉子仍在时（组长存活且启动时间相符）等它自己完成整组清理。Linux 的 pidfd 可以做到无竞态结束，但需要原生模块，留作改进 | M3 3.4「监护程序意外退出」、3.7；M13 5.7；架构 A14 |
| 3 | 强制结束时没有 `exit` | 采纳。`finalKill` 携带 `agentAlive`（Agent 根进程此刻是否存活）。`exit` 定义为三种来源：收到 `agentExit` → 真实结果；没有 `agentExit` 但收到过 `agentAlive: true` 的 `finalKill`、随后监护程序退出 → Agent 在清理最后一步被整组结束，以 `{ code: null, signal: 'SIGKILL', terminatedBy: 'cleanup' }` 发出；两者都没有 → `LOCAL_AGENT_SUPERVISOR_LOST`。`close` 照常在输出排空后发出。测试覆盖忽略 `SIGTERM` 与 `force` 取消 | M3 3.4 三个事件表、第 11 节 |

取舍说明：第 2 条使「崩溃后组长也已不在」的情况必须由人处理。这种情况需要监护程序本身也被结束（例如被外部 `kill -9`、系统内存不足），而不只是 main 崩溃：只有 main 崩溃时监护程序仍存活，它会自己完成整组清理，平台不需要人介入。
