本轮还有 **3 个需要修正的问题**。

1. **[P1] 缺少容器标记不能证明进程不属于旧容器。**
   M3 3.7 规定无标记就不发信号，但后续只明确把“读不到环境”的成员列为无法判断，没有说明“环境可读但标记缺失”也必须保留残留占用。Agent 用 `env -i` 启动的子进程仍可能留在原组内、继续写文件；若将它归为“不属于本容器”，就会放开写入保护。应明确：标记缺失属于身份未知，除非有其他证据排除归属。回应文件的保守取舍合理，需要完整写进恢复规则。

2. **[P1] 正常清理逐个发信号时，也需要防止 PID 复用。**
   M3 3.4 先列出 PID、发送 TERM，等 2.5 秒后再向“仍存在”的 PID 发 KILL。等待期间原进程可能退出，PID 被组外的无关进程复用；仅检查 PID 存在会误杀。恢复路径已经要求发送前复核启动时间，正常清理也应采用同样的身份检查，并重新核对组归属。

3. **[P2] 收到 `agentExit` 就触发 `close`，可能提前截断结果解析。**
   M3 3.2 把 `exit` 和 `close` 同时触发，但 Node 的 `close` 还意味着 stdio 已关闭。fd 3 的退出通知可能先于 stdout/stderr 被读完；现有 CLI 适配器在 `close` 时立即结束解析，可能漏掉最终回答、结尾标记或诊断。应分别定义：`exit` 报告根进程退出；`close` 等输出流排空；`container-empty` 确认清理完成。
