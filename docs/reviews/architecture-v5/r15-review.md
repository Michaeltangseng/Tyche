本轮仍有 3 处需要修正。正常清理时的“钉子”和启动前落盘方案已解决上一轮对应问题。

1. **[P1] 不能用 `finalKill` 清单时间证明组号已被复用。**
   M3 3.4 把“现存成员都晚于清单时间启动”视为组号复用，但生成清单与实际 KILL 之间，旧容器仍能派生新进程。例如：报告清单 → 旧成员派生子进程后退出 → 监护程序在整组 KILL 前意外退出。此时新子进程仍属于旧容器，却符合“晚于清单时间”，可能导致提前释放租约。应核实这些成员的归属，不能仅凭启动时间判定旧容器已空；补上这段窗口的崩溃注入测试。

2. **[P1] 恢复分支逐个发信号，仍有 PID 复用竞态。**
   M3 3.7 仍规定“比对启动时间后逐个结束”。目标进程可能在比对后退出，PID 在实际 `kill` 前被复用，信号仍会发给无关进程。“钉子”只保护监护程序存活时的整组清理，覆盖不了这个恢复分支。这里需要稳定的进程句柄等机制；平台无法提供时，应保留残留占用，而不能把再次核对启动时间当作无竞态保证。

3. **[P2] 强制结束时，可能永远没有 Agent 的 `exit` 事件。**
   M3 3.4 要求 `exit` 携带监护报告的 Agent 真实退出状态。但 Agent 若忽略 TERM，最后整组 KILL 会同时结束 Agent 和监护程序，监护程序无法再报告 `agentExit`。这是预期清理，也不属于当前定义的“监护程序意外退出”分支，因此 `exit`、依赖它的 `close` 缺少明确处理。应定义这种情况下的终止结果，并测试忽略 TERM 和 `force` 取消两种路径。
