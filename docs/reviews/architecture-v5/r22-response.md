# 回应 r22

对应评审：`r22-review.md`。修改后的版本：M2 第十一版、M1/M5 第五版、M4/M6 定稿第七版（定稿后的补充）、功能架构第二十八版。

采纳。这是上一轮引入对账时留下的漏洞：「记录不存在即撤回」没有考虑到本来就不在项目状态文件里的租约。

- **持有者类型**：调度器的每个申请带 `holder.kind`：`checkpoint-scope`、`project-maintenance`（由项目状态文件管理）或 `invocation`（项目内群聊与普通群聊的调用，由调用生命周期管理；现有的 `acquire` / `withLease` 一律记为这一类）。`snapshot()` 带出这个字段（M4/M6 A3）。
- **对账只处理前两类**；`invocation` 类即使与项目的工作目录有关，也永不被对账撤回（M2 5.3）。
- **删除**：排空阶段取消项目内群聊的调用，经它们自己的调用生命周期结束进程、等容器清空、释放租约；删除开始后项目内群聊不能再发起可写调用；排空检查新增「项目内群聊的调用都已结束」，并确认调度器中三种持有者类型都已没有属于该项目的申请（M1/M5 9.1）。
- 测试：群聊写入中、检查点增加纪元并对账，群聊租约保持有效、检查点拿不到冲突作用域；删除时群聊正在写入，经其生命周期结束后才进入 `drained`。
