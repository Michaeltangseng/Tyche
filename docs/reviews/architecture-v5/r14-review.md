本轮仍有 3 处需要修正，其中前两处影响 A14 的安全保证。

1. **[P1] TERM 到 KILL 之间仍存在进程组号复用窗口。**
   M3 3.4 规定发送 TERM，等待 2.5 秒后再发送 KILL。如果旧组在等待期间清空，组号随后被无关进程组复用，第二次信号就可能误杀。“组内还有成员时不复用”不能证明这段等待期间一直有旧成员。需要能持续保证组身份的机制；仅在发信号前再检查一次是否存在，也不能消除竞态。

2. **[P1] Agent 先运行、组号后落盘的窗口，不能仅靠环境标记恢复。**
   M3 3.7 的无组号恢复分支，只明确把“环境不可读”的候选进程视为身份未知。若 Agent 在组号落盘前启动了 `env -i` 子进程，随后 main 和监护程序都退出，这个子进程环境可读、没有标记，却仍可能继续写文件；它甚至不需要脱离原进程组。这里没有定义如何保留它对应的残留占用，也与 A14“容器身份落盘后才放行”的保证不一致。建议恢复两阶段握手：组内的门等待组号持久化确认后，才执行 Agent。

3. **[P2] 仅替换 `spawnFn` 无法接管现有取消路径。**
   M3 3.2 声称两个适配器只需替换 `spawnFn`，但现有代码直接调用全局 `process.kill(-child.pid, signal)`，成功后立即返回，根本不会经过启动器的 `child.kill()`。此时 `child.pid` 指向监护程序，信号会绕过新的 stop 协议。需要明确修改两个适配器的取消及强制终止路径，统一调用受管理的停止接口，并删除“只需换掉 spawnFn”的承诺。
