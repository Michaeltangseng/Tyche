# 回应 r8

对应评审：`r8-review.md`。修改后的版本：M4/M6 模块文档第二版、功能架构第十四版。

五条意见全部成立，全部采纳。第 1、2、5 条在仓库外的临时目录用 git 2.39 复现：冒号引用名 `update-ref` 返回 128；`*.txt text eol=lf` 下 CRLF 被存为 LF，`git diff --quiet` 返回 0；对不存在路径 `git add -f` 返回 128。

| # | 意见 | 处理 | 位置 |
| --- | --- | --- | --- |
| 1 | 副作用 id 不能作引用名 | 采纳。引用名、临时文件名中的一切 id 用 `h(id)`：UTF-8 字节的 SHA-256 小写十六进制全长，只含 `[0-9a-f]`，跨平台合法、长度固定；原始 id 写进提交说明便于诊断 | B1「名字的编码」、B3.2、B4 |
| 2 | `.gitattributes` 改写快照内容 | 采纳，取评审给出的第一种做法：影子仓库写 `info/attributes`：`* -text -eol -filter -ident -working-tree-encoding`。它优先于工作目录的任何 `.gitattributes`。实测验证：快照保存 CRLF 原样；CRLF→LF、可执行位变化都被 `git diff --quiet` 报告；文本 diff 照常输出（刻意不关闭 `diff` 属性，否则文本会被当作二进制）。另显式设置 `core.fileMode=true`、`core.symlinks=true`。候选核对、漂移检查、恢复文件、用户仓库提交的前置条件因此比较的都是原始字节与文件模式 | B1「原始字节」；架构 M4 不变量 |
| 3 | 内部符号链接别名绕过互斥 | 采纳。声明路径中已存在的部分用 `realpath` 解析，不存在的尾部接在最近的已存在祖先之后；解析结果必须在 `root` 内，否则拒绝声明。获批后才新建的别名由越界检测兜底：影子仓库把链接存为链接本身，经别名的写入显示为真实文件的改动。硬链接别名不识别，写入 Known Risks | A2.2「符号链接」、D；架构第 6 节 |
| 4 | 开放申请时项目目录尚未保护 | 采纳。启动顺序改为：恢复模式 → **从工作区文件的项目列表为所有项目目录 `holdRoot`**（不依赖各项目状态文件）→ 进程登记表恢复 → 退出恢复模式（与受保护目录重叠的申请继续等待）→ 各项目屏障独立恢复并 `openRoot`。读不出状态的项目目录保持保护、项目只读；用户可修复重试，或经确认解除这个目录的写入保护 | C |
| 5 | 强制加入不存在的文件导致失败 | 采纳。`git add -A` 照常记录所有删除（包括此前被强制加入的文件）；之后只对 `lstat` 存在的目标与回应文件执行 `git add -f`。从未存在的文件在快照中即为「不存在」，是正常值；`evaluate-submission` 明确按此处理 | B3.1 第 2 步、B2、B3.3 |

测试相应补充：含冒号 id 生成合法名字；CRLF 原始字节的保存、核对与恢复；可执行位；LFS 过滤不被调用；目标与回应文件都不存在时快照成功；符号链接别名冲突与越界拒绝；启动期间项目目录的保护；状态文件损坏时目录保持保护（D）。

请下一轮评审重点看：

1. B1 关闭 `filter` 属性后，用户仓库里的 LFS 文件在影子仓库中按原始内容保存。单文件 50 MB 的上限会把大多数 LFS 对象排除；未被排除的 LFS 文件，其指针形式与本地内容不一致，是否会影响 B7 的前置条件比较。
2. C 第 6 步「解除这个目录的写入保护」是用户的显式操作，它让一个状态未知的项目目录重新开放写入。这一入口是否需要更严格的确认。
