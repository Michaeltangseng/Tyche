| 1 | 步骤合并不能保证跨片段脱敏 | 采纳。改为**先脱敏、后切分**：每个流一个流式脱敏器，持有长度为 `W`（已知密钥最大长度与 1,024 的较大者）的未确认尾部，只放出确认安全的前缀；私钥块等到结尾，超过 64 KiB 无结尾则整体替换；放出前不落盘、不发送。步骤切分只作用在已脱敏的文本上。原始视图中的流式增量事件不再逐条保留原始形式，改为 `{ type, coalesced: true }` 加脱敏后的合并文本；非增量事件照常逐条保留。测试覆盖两种切分边界与跨增量事件 | M7/M8 3.2、4.1、第 10 节 |
| 2 | inode 比较仍有替换窗口 | 采纳。补充威胁模型：能制造竞争的是与用户同权限的进程，最坏结果是用户自己可读的文件显示在用户自己的窗口里。修法：`read` 以 `O_NOFOLLOW` 打开后，**按打开的对象反查真实路径**（Linux `/proc/self/fd/<fd>`，macOS `lsof -a -p <pid> -d <fd> -Fn`），确认在工作目录内后只经描述符读取；替换发生在打开前或打开后都不会读到外部内容。已在 macOS 上验证：打开后把目录换成外部链接，`lsof` 仍报告实际打开对象的路径。`list` 无法按描述符列目录，改为打开目录并反查路径、`readdir`、再比较 `stat` 与 `fstat`；残余窗口最多暴露外部目录的文件名、不暴露内容，写入 Known Risks。Windows 无可用接口，残余窗口写入 Known Risks | M7/M8 8.2、第 9、10 节 |
| 3 | 原始事件中的会话号 | 采纳。两层：映射器公共部分按键名递归删除会话类字段（`sessionid`、`session`、`sessionref`、`conversationid`、`threadid`、`resumeid`，不区分大小写与分隔符）；这次调用已知的原生会话号加入已知值集合，在所有字段中按值替换。测试用现有 `fixtures/agent-output/` 样例 | M7/M8 4.3、6.3 |
| 4 | 已删除文件无法 diff | 采纳。校验分三种：`read`（打开并反查）、`list`（见上）、`diff`（路径可以不存在，只做规范化与 `.git` 检查，内容一律由影子仓库的 git 读取，git 拒绝穿过符号链接的路径） | M7/M8 8.2 |
| 5 | 解析失败时绕过写入保护 | 采纳。可能写入的调用在工作目录解析失败时拒绝启动（`LOCAL_WORKDIR_UNRESOLVED`），不退回无路径声明的申请；只读调用不受影响。里程碑 2 任务单改正并补测试；M4/M6 A2.3 作为定稿后的补充写明 | 里程碑 2 任务 2.4；M4/M6 A2.3 |
