# 回应 r10

对应评审：`r10-review.md`。修改后的版本：M4/M6 模块文档第四版、功能架构第十六版、M13 第十版。

四条意见全部成立，全部修复。第 1 条的修法与建议不同，理由见下。

| # | 意见 | 处理 | 位置 |
| --- | --- | --- | --- |
| 1 | 只看大小和修改时间会漏掉变化 | **问题成立，修法不同：不每次重算全部占位哈希，而是采用与 git 文件状态缓存相同的依据。** 记录设备号、inode、大小、修改时间、**ctime** 与记录时刻，任一变化就重算；记录时刻与文件时间相差不到 2 秒时下次一律重算（对应 git 的「racy git」处理）。评审举的「写入后恢复 mtime」能被发现：任何写入与 `utimes` 都会更新 ctime，用户态无法改回。保证程度与 git 对普通文件相同，已写明限制（修改系统时钟、绕过文件系统的改写无法发现）并列入 Known Risks；文档不再说「占位随文件变化」。不每次全量重算的理由：素材多的仓库（几十 GB 二进制资源）每轮检查点要做多次快照，每次都要多读一遍全部大文件 | B3.5「占位哈希何时重算」；架构第 6 节 |
| 2 | 删除占位文件的语义没有闭合 | 采纳。每次快照先对候选路径（上次占位清单 ∪ 影子仓库 `git status` 的改动）`lstat` 并归类：不存在 → 移出索引、从排除规则与清单删除、**不写占位**，快照中即为删除；仍超限/LFS → 占位；缩小或不再属于 LFS → 从排除规则删除，按完整内容加入；换成链接或其他类型 → 从排除规则删除，按其类型保存；目标/回应文件超限 → 失败。排除规则的自动段每次整体重写，避免已不需要占位的路径被误当作不存在 | B3.1 第 2、4 步；B3.5「每次快照对占位路径的处理」；D |
| 3 | 核对用快照的失败策略缺失 | 采纳。B3.4 改为：调用前后的快照是唯一可以跳过的（跳过在关卡上作为信号显示）；其余所有快照，包括 `verify-candidate`、`verify-observed`、`drift-check`、`detect-accepted-changes` 为核对而做的快照，一律失败闭合，作为必要副作用失败暂停，「无法核对」绝不当作「无差异」 | B3.4；D |
| 4 | 占位、删除、类型变化的展示语义不统一 | 采纳。新增**统一的路径状态**：不存在、文件（完整内容）、文件（占位）、链接，四选一。所有入口（关卡、漂移条目、「文件」标签）调用 main 中同一个 `describePathChange(旧, 新)`，按表格输出变化说法与 diff 内容；漂移的可选操作只由已接受一侧的状态决定：占位时「恢复」不可用，其余状态两种操作都可用（已接受为不存在时恢复即删除，为链接时重建链接）。占位只用于普通文件，链接总是按链接保存 | B3.5「统一的路径状态」；B5 第 6 步；M13 5.8.1 |

测试补充：删除、缩小、换成链接三种占位时序；`utimes` 恢复 mtime 后由 ctime 触发重算；racy 窗口强制重算；核对快照超限时实例暂停、不进入接受；每一种「旧 → 新」组合在三个入口得到相同输出与可选操作（D）。
