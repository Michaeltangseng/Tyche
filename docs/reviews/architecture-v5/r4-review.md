本轮修改方向成立，但还有 **4 处时序缺口**需要补齐。当前改动都在暂存区，我检查了 `git diff --cached`。

1. **[P1] 漂移处理可能与原接受事务交错，覆盖刚确认的新版本。**
   M2 在进入 `accepting` 时就发布漂移条目；又允许确认观察快照并形成新版本，却没有要求原接受事务先完成。例如接受 A 的提交正在失败重试，用户先确认漂移 B；随后原提交成功，转移表又登记 A，而漂移已经解决。建议条目立即展示，但处理必须排在原接受事务完成之后，并绑定它对应的接受版本。

2. **[P1] 协调操作无条件越过暂停，可能提前释放恢复所需的租约。**
   M2 允许释放租约越过暂停。恢复链中，若已经获取租约，但核对或恢复文件失败，后面的释放仍可执行；用户重试时又从失败步骤继续，此时已没有租约保护。建议区分“取消后的清理”和“正常流程中的释放”：若失败后释放了租约，重试必须重新获取并重新核对内容。

3. **[P1] 纪元校验只能阻止尚未启动的操作，无法撤销已经在等待的租约申请。**
   M2 声称正在进行的恢复随纪元作废，但 5.3 只在副作用启动前校验。恢复申请已经进入调度器等待时，上游重开使纪元变化，旧申请仍可能稍后拿到租约；后续恢复和释放又因旧纪元被跳过，留下无人释放的租约。建议明确取消等待申请、获批后的二次校验，以及旧操作的释放保证；正在写入的恢复也需要完成或停止后的结果隔离规则。

4. **[P2] 恢复屏障把“等待租约”误当成“已经持有”，正常状态也会被判为冲突。**
   M2 为所有“处理中”的恢复漂移重建租约，并断言不会冲突。但合法路径就是：里程碑正在评审、持有工作目录租约，漂移恢复正在等待文件租约，此时崩溃。重启后两者申请必然冲突，这不是状态损坏。建议分别持久化“等待申请”和“已获批”，屏障只恢复已持有的租约，等待请求在屏障后重新排队。
